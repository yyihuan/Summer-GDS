## 1. 文档目标

本文档用于整理 Summer-GDS 重构后的需求边界，作为后续重新设计前后端和 YAML 协议的依据。

本文档只保留当前已经达成一致的需求，不再机械继承旧实现中的历史包袱。

## 2. 产品定位

Summer-GDS 的主要用户是 GUI 用户。

当前阶段，系统的核心使用方式是：

- 用户通过 GUI 编辑图形配置
- GUI 生成规范 YAML
- 后端根据 YAML 生成 GDS

因此：

- GUI 是主入口
- YAML 是正式配置协议，同时承担导入导出和持久化作用
- 直接手写 YAML 批量生成不是当前重点

## 3. 设计原则

### 3.1 前后端职责分离

前端负责：

- 提供易用的输入方式
- 做单值输入、简化模式、批量填充等交互
- 将简化输入展开为无歧义的正式 YAML

后端负责：

- 读取结构稳定的 YAML
- 执行几何生成
- 生成 GDS

结论：

- 后端不接受复杂字符串规则
- 后端不承担含糊输入的推导责任
- 正式 YAML 必须是展开后的明确结构

### 3.2 前端按产品语义建模

前端按三类 shape 组织：

- `base_shape`
- `rings`
- `via`

这样符合用户操作语义：

- `base_shape` 和 `rings` 属于基础光刻图形
- `via` 属于工艺处理图形

### 3.3 后端按几何原语建模

后端建议拆成两层：

- 基础几何层：`polygon` / `circle`
- 生成操作层：`solid` / `single_ring` / `ring_array`

对应关系：

- `base_shape -> solid`
- `via -> single_ring`
- `rings -> ring_array`

这样可以在几何实现上复用 `rings` 和 `via` 的内核逻辑，同时保留前端上的业务语义区分。

## 4. 核心对象模型

本期系统对外暴露三类 shape：

- `base_shape`
- `rings`
- `via`

基础几何定义方式当前支持两种：

- `polygon`
- `circle`

未来可扩展其它生成器，但本期不做。

## 5. 顶层配置结构

建议保留三段顶层结构：

- `global`
- `gds`
- `shapes`

职责如下：

- `global`：全局默认设置、图层映射等
- `gds`：输出相关配置
- `shapes`：形状定义

YAML 是正式协议，字段类型必须稳定、明确。

## 6. 图层与 `layer_mapping`

### 6.1 图层正式格式

图层格式必须是：

```yaml
layer: [layer_num, datatype]
```

这是后端正式协议。

不接受：

- 直接将字符串 layer 名称作为 `shape.layer`

### 6.2 layer name 映射

需要支持 `layer_name -> [layer_num, datatype]` 的映射能力，但优先级较低。

用途：

- GUI 显示图层名称
- 提高 YAML 可读性
- 后续做图层管理

### 6.3 `layer_mapping` 的定位

`layer_mapping` 用于保存：

- `layer_num`
- `datatype`
- `layer_name`

它不属于标准 GDSII 主文件能力。

结论：

- 标准 GDSII 本体只保存 `layer` 和 `datatype`
- `layer_mapping` 不能假设被标准 GDS 软件自动识别
- 当前阶段 `layer_mapping` 只作为本软件自用的 YAML 配套文件
- 暂时不做 KLayout 专有兼容

## 7. 形状体系

### 7.1 `base_shape`

`base_shape` 是基础光刻图形。

它可以：

- 直接生成实心图形
- 作为 `rings` 的基础几何
- 作为 `via` 的基础几何

### 7.2 `rings`

`rings` 是基于基础图形向外扩展生成的一组环。

它属于基础光刻图形的一部分。

### 7.3 `via`

`via` 是工艺处理图形。

它通过同一基础图形的外扩和内缩轮廓做布尔差，生成一个单环结构。

虽然 `via` 和 `rings` 在后端实现上存在重合，但在产品语义和前端交互上必须独立。

## 8. 几何输入规则

### 8.1 `polygon` 输入

`polygon` 使用显式顶点输入。

要求：

- 点分隔符固定为 `;`
- 单点格式为 `x,y`
- 至少 3 个点

示例：

```yaml
vertices: "0,0;10,0;10,10;0,10"
```

### 8.2 顶点方向

顶点顺序规范为顺时针。

要求：

- 如果输入为逆时针，系统自动转为顺时针
- 后续几何算法统一基于顺时针顶点序处理

### 8.3 `circle` 输入

`circle` 不直接输入顶点，而使用圆参数描述。

建议字段：

```yaml
center_x: 0
center_y: 0
radius: 10
```

说明：

- 后端可以内部将 circle 离散为轮廓
- 但这只是实现细节，不应暴露为用户输入形式

### 8.4 哪些 shape 支持哪种基础几何

当前要求：

- `base_shape` 支持 `polygon` 和 `circle`
- `rings` 支持基于 `polygon` 和 `circle`
- `via` 支持基于 `polygon` 和 `circle`

## 9. `zoom` 规则

### 9.1 实心图形

对于实心图形：

- `base_shape.geometry_type = polygon`
- `base_shape.geometry_type = circle`

只接受单值 `zoom`。

语义：

- 表示整体轮廓偏移

### 9.2 环形图形

对于 `rings`：

- `zoom` 接受两个值

格式：

```yaml
zoom: [inner_delta, outer_delta]
```

语义：

- `inner_delta`：内边界移动量
- `outer_delta`：外边界移动量

前端简化规则：

- 如果用户只输入一个值 `a`
- 前端展开为 `[a, -a]`

### 9.3 `via`

`via` 的核心偏移参数建议直接使用：

- `inner_zoom`
- `outer_zoom`

不再把它混入单值 `zoom` 语义中。

## 10. `base_shape` 需求

### 10.1 基本定义

`base_shape` 表示一个实心基础图形。

建议字段：

- `type: base_shape`
- `geometry_type: polygon | circle`
- `layer`
- `zoom`
- 基础几何参数
- 倒角配置

### 10.2 polygon 型 `base_shape`

支持：

- 顶点定义
- 单值 `zoom`
- 圆弧倒角
- 每个角独立倒角半径

不需要：

- 顶点量化配置
- adaptive 倒角

### 10.3 circle 型 `base_shape`

支持：

- 圆心和半径定义
- 单值 `zoom`

不支持：

- 手工输入倒角

前端要求：

- circle 尽量与 polygon 使用统一表单布局
- 倒角区域显示但置灰
- 对应 YAML 中倒角字段写为 `null`

## 11. `rings` 需求

### 11.1 基本定义

`rings` 表示基于基础图形生成的一组环。

前端上应支持两种基础输入来源：

- `polygon`
- `circle`

### 11.2 基础几何来源

`rings` 必须支持：

- 基于 `polygon` 定义
- 基于 `circle` 定义

要求：

- 前端先选择基础几何类型
- 再显示对应输入区域
- 公共的 `rings` 参数区保持一致

### 11.3 环数量

`rings` 必须显式控制环数量。

建议字段：

```yaml
ring_count: 3
```

要求：

- `ring_count` 为正整数

### 11.4 环宽与环间距

`rings` 的后端正式协议应统一为展开后的独立参数。

建议字段：

```yaml
ring_widths: [2, 2, 3]
ring_spaces: [1, 1, 2]
```

说明：

- 每个环都有独立环宽
- 每个环都有独立环间距
- 前端可以支持单值简化输入
- 但导出 YAML 时必须展开为完整列表

### 11.5 `rings` 的生成规则

`rings` 的生成起点固定为：

- `base_shape` 作为最内层环的内边界

具体规则：

- 最内层环的内边界相对于 `base_shape` 的偏移为 `0`
- 最内层环的外边界 = `base_shape` 向外扩张一个环宽
- 后续每一环都基于前一环继续向外扩展

也就是说：

- 第 1 个环由 `base_shape` 直接生成
- 第 2 个及之后的环基于前一环的外边界继续向外生长
- 不是每一环都重新相对原始 `base_shape` 单独计算

### 11.6 `rings` 的 `zoom`

`rings` 使用：

```yaml
zoom: [inner_delta, outer_delta]
```

前端可支持单值简化输入，但必须先展开再写入 YAML。

### 11.7 `rings` 的倒角

`rings` 只保留圆弧倒角。

如果 `rings` 基于 `polygon`：

- 允许配置倒角

如果 `rings` 基于 `circle`：

- 前端倒角输入区置灰
- YAML 中倒角写为 `null`

## 12. `via` 需求

### 12.1 基本定义

`via` 是基于基础图形生成的单环工艺图形。

几何定义：

- 同一基础图形生成外扩轮廓
- 同一基础图形生成内缩轮廓
- 两者做布尔差
- 保留中间环形区域

### 12.2 基础几何来源

`via` 必须支持：

- 基于 `polygon`
- 基于 `circle`

### 12.3 核心参数

`via` 的核心参数是：

- 基础几何定义
- `inner_zoom`
- `outer_zoom`
- `layer`

如果需要保留关联关系，则只保留：

- `base_shape_id`

不保留旧系统中复杂的派生元数据链。

### 12.4 `via` 的倒角

如果 `via` 基于 `polygon`：

- 允许配置倒角

如果 `via` 基于 `circle`：

- 前端倒角区域置灰
- YAML 中倒角写为 `null`

## 13. 倒角需求

### 13.1 倒角类型

只保留一种倒角：

- 圆弧倒角

不保留：

- adaptive 倒角

### 13.2 总体规则

倒角半径必须能独立控制每一个角。

正式 YAML 中，倒角必须写成显式列表，不允许只保留简写值。

前端可以支持单值输入、批量填充等简化交互，但最终必须展开为正式结构。

### 13.3 `base_shape` 的倒角

仅适用于 polygon 型 `base_shape`。

规则：

- YAML 中倒角列表长度必须与角数量一致
- 列表第一个值对应 polygon 第一个点所在的角
- 后续值依次对应后续点所在的角

例如五边形：

```yaml
fillet:
  radii: [a1, a2, a3, a4, a5]
```

前端简化规则：

- 如果用户输入单值 `a`
- 前端展开为：

```yaml
fillet:
  radii: [a, a, a, a, a]
```

### 13.4 `via` 的倒角

仅适用于 polygon 型 `via`。

如果基础图形是五边形，则倒角列表长度应为 `10`。

顺序固定为：

- 先是内边界，从第一个顶点开始顺时针一圈
- 再是外边界，从第一个顶点开始顺时针一圈

例如：

```yaml
fillet:
  radii: [
    inner_1, inner_2, inner_3, inner_4, inner_5,
    outer_1, outer_2, outer_3, outer_4, outer_5
  ]
```

前端默认简化规则：

- 用户输入单值 `a`
- 该值表示内边界倒角半径
- 外边界默认展开为 `a + width`

其中：

- `width = outer_zoom - inner_zoom`

这样默认保证内外边界倒角同心。

单值输入展开示意：

```yaml
fillet:
  radii: [a, a, a, a, a, a+width, a+width, a+width, a+width, a+width]
```

如果用户手工输入完整列表，则以后端显式列表为准。

### 13.5 `rings` 的倒角

仅适用于 polygon 型 `rings`。

circle 型 `rings` 的倒角固定为：

```yaml
fillet: null
```

#### 13.5.1 最内侧环

最内侧环沿用 `via` 的单环规则。

例如五边形最内侧环：

- 需要一组长度为 `10` 的倒角定义
- 顺序仍是内边界一圈，再外边界一圈

#### 13.5.2 单值输入时的默认规则

如果 `rings` 由前端单值输入生成，则默认要求：

- 所有环的内外边界同心

即：

- 每一环的外边界倒角半径 = 对应内边界倒角半径 + 该环环宽

#### 13.5.3 独立控制内外边界时的规则

如果用户独立控制内外边界，则默认几何约束为：

- 所有环的内边界彼此同心
- 所有环的外边界彼此同心

不强制要求每一环内部仍然由一个固定宽度差自动推导。

#### 13.5.4 推荐 YAML 结构

`rings` 的倒角推荐使用“每环一个对象”的结构，而不是平铺成一维长列表。

示例：五边形，3 环

```yaml
fillet:
  rings:
    - inner: [1, 1, 1, 1, 1]
      outer: [3, 3, 3, 3, 3]
    - inner: [1, 1, 1, 1, 1]
      outer: [3, 3, 3, 3, 3]
    - inner: [1.5, 1.5, 1.5, 1.5, 1.5]
      outer: [4.5, 4.5, 4.5, 4.5, 4.5]
```

这样更容易：

- 区分第几环
- 区分内外边界
- 做前端表单
- 做后端校验

### 13.6 circle 的倒角

对于所有基于 `circle` 的图形：

- 倒角字段统一为 `null`

原因：

- circle 没有用户可见的离散角
- 不应向用户暴露伪造出来的角倒角配置

### 13.7 倒角精度

倒角精度不再作为图形配置项暴露给用户。

改为由系统根据倒角半径自动决定。

当前规则：

- 倒角半径 `<= 20um` 时，使用 `0.001um` 精度
- 倒角半径 `> 20um` 时，使用 `0.01um` 精度

后续可能调整阈值或增加更多精度档位，因此实现上应设计为独立策略。

## 14. GDS 输出需求

### 14.1 基本输出

当前阶段只需要：

- 从 GUI/YAML 生成新的 GDS

不需要：

- 读入已有 GDS 后继续加工

### 14.2 整体缩放

系统需要支持对整个 GDS 做整体缩放。

目标：

- 在不改变图形相对结构的前提下统一放大或缩小整个版图

建议字段：

- `gds.scale`

实现方向：

- 优先考虑通过数据库精度或等效比例换算实现

要求：

- 缩放作用于整个版图
- 保持各图形之间相对位置和比例不变

## 15. 前端需求

### 15.1 界面统一性

前端应尽量使用统一的 shape 编辑体验。

具体要求：

- `polygon` 和 `circle` 尽量共用同一套表单结构
- `rings` 和 `via` 也应先选基础几何类型，再显示对应输入区
- 不适用字段尽量置灰，而不是彻底隐藏

### 15.2 倒角输入的前端职责

前端需要支持：

- 单值输入
- 批量填充
- 自动展开为正式 YAML 列表

后端不负责保留这些交互层面的简写输入。

### 15.3 GUI 元数据

GUI 元数据应以 YAML 注释形式输出，以提高可读性。

要求：

- 元数据不进入正式业务字段
- 后端不依赖这些元数据

## 16. GDS 反向读取工具

前端需要提供一个工具页或弹窗，用于读取现有 GDS 并提取图形轮廓。

目标：

- 上传 GDS 文件
- 输出每个图形的顶点列表
- 顶点顺序统一为顺时针
- 结果可直接用于后续生成 YAML

输出内容至少包括：

- 所属 layer
- 顶点列表

如果读取过程中无法稳定区分同一 layer 内的多个独立图形，则引入约束：

- 每个 layer 只能有一个图形

如果不满足该约束，工具应报错或提示，而不是猜测。

## 17. 明确不保留的旧能力

重构时明确不保留：

- `star` 生成器
- adaptive 倒角
- 复杂字符串规则解析
- 顶点精度量化作为用户配置项
- 从已有 GDS 继续叠加生成的主流程
- 复杂的历史派生元数据链
- 将 GUI 元数据写入正式业务 YAML 字段

## 18. 低优先级需求

低优先级但建议预留：

- `layer_mapping` 的真实实现
- layer name 在 GUI 中的展示与编辑
- YAML 注释保留策略
- `base_shape_id` 的最小关联设计
- GDS 读取工具的复杂异常处理

## 19. 总结

重构后的 Summer-GDS 应是一个以 GUI 为主入口、以结构化 YAML 为正式协议的 GDS 生成系统。

前端按 `base_shape`、`rings`、`via` 三类产品语义组织，后端按“基础几何 + 生成原语”复用实现。

系统聚焦：

- `polygon` 和 `circle` 两类基础几何
- `rings` 和 `via` 两类环形生成能力
- 顺时针顶点规范
- 明确的结构化参数
- 可独立控制每个角的圆弧倒角
- 前端简化输入、后端只处理确定数据
